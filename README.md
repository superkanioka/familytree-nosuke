# 家系図作成アプリ

A3横向きを初期値に、A4横向きも選べるクライアントサイド完結の家系図作成アプリです。人物データを編集しながらCanvasでプレビューし、ブラウザの印刷機能から印刷・PDF保存できます。

## 実行方法

1. `index.html` をブラウザで開きます。
2. 左側のフォームで人物を追加・編集します。
3. 親と配偶者は `親を選ぶ` / `配偶者を選ぶ` から一覧で選びます。IDを覚える必要はありません。親を選ぶと世代が自動で決まります。
4. 続柄は候補を選ぶか自由入力します。`候補` を押すと、登録済みの親や配偶者から `第N子` や `配偶者` を自動入力できます。
5. `用紙サイズ` で `A3横`（初期値）または `A4横` を選びます。選択はブラウザの `localStorage` に保存され、未保存時や不正値はA3に戻ります。
6. `JSON書き出し` で保存用リンクを作り、`JSON読込` でバックアップを読み込めます。
7. `配置調整` を押すと、Canvas上の人物枠をドラッグして位置を調整できます。位置は自動的に保存され、`自動配置に戻す` で全員を自動配置へ戻せます。
8. `印刷` を押すと、選択した用紙サイズでブラウザの印刷画面が開きます。PDFとして保存する場合は、ブラウザの印刷画面で保存先にPDFを選びます。

Canvas上の人物枠をクリックすると、その人物を編集できます。操作はツールバーの `元に戻す` / `やり直す`（`Ctrl+Z` / `Ctrl+Shift+Z`）で取り消せます。

ローカルサーバーで確認したい場合は、任意の静的サーバーでこのフォルダを配信してください。

```powershell
python -m http.server 8000
```

その後、ブラウザで `http://localhost:8000/` を開きます。

## ソース構成とビルド

配布物は従来どおり `index.html` 1枚ですが、これは `src/` から生成しています。**`index.html` を直接編集しないでください。**

```
src/
  index.template.html  HTMLの骨組み（{{styles}} {{icons}} {{script}} を埋める）
  styles.css           Material 3のスタイル
  icons.svg            SVGアイコンのスプライト
  data.js              人物データの正規化・入力値の解釈・続柄の推定（DOMなし）
  layout.js            世代ごとの自動配置（DOMなし）
  draw.js              Canvas描画（DOMなし、配色は引数で受け取る）
  app.js               DOM・localStorage・イベント配線
build.mjs              src/ から index.html を生成する（依存パッケージなし）
```

```bash
node build.mjs           # index.html を生成する
node build.mjs --check   # index.html が src/ と一致するか確認する
```

`build.mjs` は各モジュールから `import` / `export` を取り除いて依存順に連結し、構文を検査してから差し込みます。生成した `index.html` はコミットするので、利用者は今までどおりファイルを開くだけで使えます。

## テスト

```bash
npm test
```

次の4つを順に実行します。

1. `node --test "tests/unit/*.test.js"` — `data.js` / `layout.js` / `draw.js` のユニットテスト（55件）
2. `node build.mjs --check` — `index.html` が `src/` から作り直した結果と一致するか
3. `bash tests/smoke.sh` — 静的配信と必須UIの存在確認
4. `bash tests/browser.sh` — ヘッドレスChromiumでの実操作（71件）

`draw.js` のテストはCanvasの代わりに呼び出しを記録するスタブを使います。`document` や `window` に触れているとNodeで例外になるため、描画ロジックがDOMから切り離されていることもここで担保しています。

### テストの補足

- `tests/smoke.sh` はNode.jsもChromiumも使わず、静的配信と必須UIの存在だけを確認します（`python3` のみ必要）。
- `tests/browser.sh` はChromiumが見つからない場合スキップします。使うバイナリは `CHROME=/path/to/chrome bash tests/browser.sh` で指定できます。検証内容は `tests/ui-checks.js`（通常操作）と `tests/storage-checks.js`（保存できない環境）にあります。
- 見た目の最終確認は、Chromeなどで `index.html` か `http://127.0.0.1:8000/` を開いて行います。

## データを失わないための仕組み

家族など複数人で使うことを想定し、誤操作でデータが消えないようにしています。

- **削除は必ず確認します。** 削除ボタンは「いま編集している人物」を対象にし、確認ダイアログを挟みます。
- **元に戻せます。** 追加・保存・削除・サンプル復元・JSON反映・JSON読込・自動配置に戻す・バックアップ復元は最大50件まで遡れます（`Ctrl+Z`、ツールバー、直後なら画面左下のスナックバー）。`Ctrl+Shift+Z` でやり直せます。文字入力中はブラウザ本来の取り消しを優先します。
- **IDを扱わせません。** IDは保存時に自動で採番し、画面には出しません。手入力で既存の人物を取り違えて上書きすることが起きません。
- **入力の誤りは項目ごとに知らせます。** 氏名が空、世代が数字でないといった誤りは、該当の入力欄の下に理由を出して保存を止めます。
- **自動バックアップを5件保持します。** 保存のたびに `localStorage` の `familytree.backups` へスナップショットを積み、JSON欄の下に日時付きで並べて復元できます。
- **保存できない環境を検知します。** プライベートモードや容量超過で `localStorage` に書けないとき、起動時と保存時に消えない警告を出します（JSON書き出しでバックアップしてください）。

## 画面デザイン

UIはMaterial 3（Material You）のガイドラインに沿ったスタイルにしています。

- 配色はティール系シードのM3トーナルパレットで、`--md-*` カスタムプロパティとして `:root` に定義しています。旧来の `--accent` などはこれらのエイリアスとして残しています。
- OSの設定に合わせてライト / ダークテーマを自動で切り替えます（`prefers-color-scheme`）。用紙プレビューは印刷結果と一致させるため、ダークテーマでも白のままです。
- ボタンはM3のFilled / Tonal / Errorの3種類（`既定` / `.secondary` / `.danger`）で、押下時にリップルが広がります。入力欄はOutlined text fieldスタイルです。
- サイドバーは編集フォーム・人物一覧・JSONの3枚のカードに分割し、人物一覧はアバター付きのリストアイテムとして選択中の人物をハイライトします。
- ツールバーはトップアプリバーとして固定表示し、人数・世代の情報はチップで表示します。
- アイコンは外部フォントを使わず、`index.html` 内のSVGスプライト（`#ic-*`）で完結させています。オフラインでもそのまま開けます。
- 親・配偶者はモーダルの人物ピッカー（検索付きリスト）で選びます。既に選んだ人物と自分自身は候補から外れます。
- 入力エラーはM3のerror stateとsupporting textで、該当の入力欄に出します。
- `prefers-reduced-motion` が有効な環境ではアニメーションを無効化します。
- 印刷時はサイドバーとツールバーを非表示にし、用紙の角丸・影も外して用紙いっぱいに描画します。

## データモデル

人物データは以下の形を基本にしています。

IDは保存時に自動採番されます（画面には出しません）。JSONを直接編集する場合のみ意識してください。

```json
{
  "id": 1,
  "name": "山田 太郎",
  "relation": "長男",
  "years": "1930-2005",
  "generation": 0,
  "position": {"x": 0.5, "y": 0.2},
  "spouseId": 2,
  "spouseIds": [2],
  "spouseRelationshipTypes": {"2": "married"},
  "parentIds": [],
  "parentRelationshipTypes": {},
  "relationshipType": "married",
  "relationshipMeta": {}
}
```

- `generation`: 0が最上位世代です。5世代以上も扱えるようにしています。
- `position`: 手動配置した人物枠の位置です。用紙全体に対する0〜1の正規化座標で保存し、未指定または `null` の場合は自動配置します。
- `relation`: 「長男」「母」「配偶者」など、基準人物から見た続柄です。フォームでは候補から選ぶことも自由入力もできます。Canvas上の人物枠にも表示します。
- `relation` の自動候補は、同じ親を持つ人物の生年・ID順から `第N子` を提案します。性別を推測せず、必要に応じて手動で修正できます。
- `spouseId`: 旧形式互換用の代表配偶者IDです。保存時は `spouseIds` と相手側の配偶者情報も可能な範囲で同期します。
- `spouseIds`: 複数の配偶者IDを保持する拡張フィールドです。画面では人物ピッカーで選びます。`spouseId` は旧形式との互換用に先頭のIDを保持します。
- `spouseRelationshipTypes`: 配偶者IDごとの `married`、`divorced`、`widowed`、`partner` を保持します。画面では配偶者1人ずつに種別を設定でき、相手側の人物にも同じ種別が入ります。
- `parentIds`: 親IDの配列です。0人、1人、2人を想定しています（画面では2人を超えて選べません）。
- `parentRelationshipTypes`: 親IDごとの関係種別です。`biological`（実親）、`adopted`（養親）、`step`（継親）、`unknown`（不明）を保持します。未指定の既存データは実親として扱います。
- `relationshipType`: `married`、`divorced`、`widowed`、`partner` などを保持できます。
- `relationshipMeta`: 離婚、死別、養子などの詳細拡張用の空きフィールドです。

`localStorage` には次のキーを使います。

- `familytree.people`: 現在の人物データです。
- `familytree.paperSize`: 選択中の用紙サイズです。
- `familytree.backups`: 自動バックアップ（最大5件、新しい順）です。

## レイアウト方針

- `generation` ごとに横一列へ自動グルーピングします。
- 同世代の配偶者ネットワークはひとまとまりにして隣接配置し、関係ごとに線で結びます。複数配偶者にも対応します。
- 親子関係は親側から下に伸ばし、子の世代で横バスラインへ分岐します。
- 養親・継親・不明な親子関係は、親子線を点線系の表示にして区別します。
- 手動配置を保存した人物は、画面サイズやA3/A4を切り替えても同じ比率位置を基準に再配置します。
- 兄弟姉妹や夫婦単位が増えた場合も全体を選択中の用紙比率のCanvas内に収まるよう自動スケーリングします。

## 印刷方針

Canvasのプレビューをブラウザの印刷対象として表示し、選択中のA3横（420 x 297 mm）またはA4横（297 x 210 mm）で印刷します。PDFファイルが必要な場合は、ブラウザの印刷画面で保存先にPDFを選択してください。

## 補足

配布は単一ファイルのまま、ソースは `src/` に分割しています。描画（`draw.js`）・配置（`layout.js`）・データ（`data.js`）はDOMから切り離してあるため、ユニットテストから直接呼び出せます。
