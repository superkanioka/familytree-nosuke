# 家系図作成アプリ

A3横向きを初期値に、A4横向きも選べるクライアントサイド完結の家系図作成アプリです。人物データを編集しながらCanvasでプレビューし、ブラウザの印刷機能から印刷・PDF保存できます。

Svelte + Vite で作っています。開発は `npm run dev`、配布物は `npm run build` で `dist/index.html`（JS/CSSを内包した1枚）に収まります。ビルド後の `dist/index.html` は `file://` でそのまま開いても動きます。

## 実行方法

1. 開発中は `npm install` のあと `npm run dev` で開発サーバーを起動し、表示されたURLを開きます。配布物を確認するなら `npm run build` 後に `dist/index.html` を開きます。
2. 左側のフォームで人物を追加・編集します。
3. 親と配偶者は `親を選ぶ` / `配偶者を選ぶ` から一覧で選びます。IDを覚える必要はありません。親を選ぶと世代が自動で決まります。
4. 続柄は候補を選ぶか自由入力します。`候補` を押すと、登録済みの親や配偶者から `第N子` や `配偶者` を自動入力できます。
5. 性別・備考・写真を設定できます。生没年に終年を入れると、自動で故人として扱います（チェックで切り替えられます）。
6. `用紙サイズ` で `A3横`（初期値）・`A4横`・`B4横`・`A3縦`・`A4縦` から選びます。選択はブラウザの `localStorage` に保存され、未保存時や不正値はA3に戻ります。
7. `JSON書き出し` で保存用リンクを作り、`JSON読込` でバックアップを読み込めます。
8. `配置調整` を押すと、Canvas上の人物枠をドラッグして位置を調整できます。位置は自動的に保存され、`自動配置に戻す` で全員を自動配置へ戻せます。
9. `画像で保存` を押すと、用紙サイズのPNG（約150dpi）を書き出します。共有に対応した端末では共有シートが開きます。
10. `印刷` を押すと、選択した用紙サイズでブラウザの印刷画面が開きます。PDFとして保存する場合は、ブラウザの印刷画面で保存先にPDFを選びます。

Canvas上の人物枠をクリックすると、その人物を編集できます。操作はツールバーの `元に戻す` / `やり直す`（`Ctrl+Z` / `Ctrl+Shift+Z`）で取り消せます。

開発サーバーは次のように起動します。

```bash
npm run dev
```

配布物（`dist/`）を静的サーバーで確認する場合は `npm run preview` を使います。

## アプリとして使う（PWA）

ビルドした `dist/index.html` をそのまま開く使い方に加えて、https（またはローカルサーバー）で配信すると**インストールできるアプリ**として使えます。

- Android/Chromeでは、ツールバーに `アプリとして追加` が出ます。ホーム画面から単独ウィンドウで起動します。
- iOS/Safariでは、共有メニューの「ホーム画面に追加」で同じことができます。
- 一度開けば**オフラインでも起動**します（Service Workerが本体とアイコンをキャッシュします）。
- 更新は、オンラインなら開くたびに最新が取得されます。オフラインのときだけキャッシュを使います。

### GitHub Pagesで配る

`main` への push で `.github/workflows/pages.yml` がテスト＋ビルドを通し、`dist/`（`index.html` / `manifest.webmanifest` / `sw.js` / `icons/`）を公開します。**初回だけ、リポジトリの Settings > Pages で Source を「GitHub Actions」に変更してください。**

`file://` で開いた場合、Service Workerは登録されません（ブラウザの制約）。アプリの機能はすべて従来どおり動きます。

## ソース構成とビルド

Svelte + Vite 構成です。`npm run build` で `vite-plugin-singlefile` がJS/CSSを1枚の `dist/index.html` に内包し、PWA用の `manifest.webmanifest` / `sw.js` / `icons/`（`public/`）を横に並べます。

```
index.html             Viteのエントリ（SVGアイコンのスプライトとマウント先を持つ）
src/
  main.js              Svelteアプリのマウント
  App.svelte           画面全体の組み立て（レイアウト・印刷@page・キー操作・PWA配線）
  app.css              Material 3をベースにしたグローバルスタイル
  data.js              人物データの正規化・下書きの検証・続柄の推定（DOMなし）
  layout.js            世代ごとの自動配置（DOMなし）
  draw.js              Canvas描画（DOMなし、配色は引数で受け取る）
  lib/
    store.svelte.js    状態とロジックの中枢（localStorageと履歴。DOM/Canvasには触れない）
    dialogs.svelte.js  ピッカー・確認ダイアログをPromiseで開く共有状態
  components/          フォーム・一覧・ツールバー・プレビュー・ダイアログ等のSvelte部品
public/
  manifest.webmanifest PWAのマニフェスト
  sw.js                Service Worker（本体はネット優先・アイコンはキャッシュ優先）
  icons/               アプリアイコン
tools/make-icons.sh    アイコンPNGを作り直す（Chromiumが必要）
```

`data.js` / `layout.js` / `draw.js` はDOMから切り離した純粋モジュールで、Svelteからも `tests/unit` からも同じものを読み込みます。

```bash
npm run dev      # 開発サーバー
npm run build    # dist/index.html（単一HTML）を生成
npm run preview  # dist/ をローカル配信して確認
```

## テスト

```bash
npm test
```

次の2つを順に実行します。

1. `node --test "tests/unit/*.test.js"` — `data.js` / `layout.js` / `draw.js` のユニットテスト（80件）
2. `vite build` — 本番ビルドが通ること（Svelteのコンパイルと単一HTML生成の検証）

`draw.js` のテストはCanvasの代わりに呼び出しを記録するスタブを使います。`document` や `window` に触れているとNodeで例外になるため、描画ロジックがDOMから切り離されていることもここで担保しています。

見た目や実操作の最終確認は、`npm run dev` か、ビルドした `dist/index.html` をブラウザで開いて行います。

## データを失わないための仕組み

家族など複数人で使うことを想定し、誤操作でデータが消えないようにしています。

- **削除は必ず確認します。** 削除ボタンは「いま編集している人物」を対象にし、確認ダイアログを挟みます。
- **元に戻せます。** 追加・保存・削除・サンプル復元・JSON反映・JSON読込・自動配置に戻す・バックアップ復元は最大50件まで遡れます（`Ctrl+Z`、ツールバー、直後なら画面左下のスナックバー）。`Ctrl+Shift+Z` でやり直せます。文字入力中はブラウザ本来の取り消しを優先します。
- **IDを扱わせません。** IDは保存時に自動で採番し、画面には出しません。手入力で既存の人物を取り違えて上書きすることが起きません。
- **入力の誤りは項目ごとに知らせます。** 氏名が空、世代が数字でないといった誤りは、該当の入力欄の下に理由を出して保存を止めます。
- **自動バックアップを5件保持します。** 保存のたびに `localStorage` の `familytree.backups` へスナップショットを積み、JSON欄の下に日時付きで並べて復元できます。
- **保存できない環境を検知します。** プライベートモードや容量超過で `localStorage` に書けないとき、起動時と保存時に消えない警告を出します（JSON書き出しでバックアップしてください）。

## 画面デザイン

UIはMaterial 3（Material You）のガイドラインに沿ったスタイルにしています。

- 配色はティール系シードのM3トーナルパレットで、`--md-*` カスタムプロパティとして `:root` に定義しています。家系図の線色は `--marriage` / `--child` として持ち、Canvasが読み取ります。
- OSの設定に合わせてライト / ダークテーマを自動で切り替えます（`prefers-color-scheme`）。用紙プレビューは印刷結果と一致させるため、ダークテーマでも白のままです。
- ボタンはM3のFilled / Tonal / Errorの3種類（`既定` / `.secondary` / `.danger`）で、押下時にリップルが広がります。入力欄はOutlined text fieldスタイルです。
- サイドバーは編集フォーム・人物一覧・JSONの3枚のカードに分割し、人物一覧はアバター付きのリストアイテムとして選択中の人物をハイライトします。
- ツールバーはトップアプリバーとして固定表示し、人数・世代の情報はチップで表示します。
- アイコンは外部フォントを使わず、`index.html` 内のSVGスプライト（`#ic-*`）で完結させています。オフラインでもそのまま開けます。
- 親・配偶者はモーダルの人物ピッカー（検索付きリスト）で選びます。既に選んだ人物と自分自身は候補から外れます。
- 920px以下では、家系図を主役にして編集フォームをボトムシートに畳みます。つまみをタップすると開きます。
- 入力エラーはM3のerror stateとsupporting textで、該当の入力欄に出します。
- 性別は□（男性）・○（女性）の記号で示し、故人は枠の地色を落として表します。印刷は白黒でも読み取れます。
- `prefers-reduced-motion` が有効な環境ではアニメーションを無効化します。
- 印刷時はサイドバーとツールバーを非表示にし、用紙の角丸・影も外して用紙いっぱいに描画します。

## データモデル

人物データは以下の形を基本にしています。

IDは保存時に自動採番されます（画面には出しません）。JSONを直接編集する場合のみ意識してください。

```json
{
  "id": 1,
  "name": "山田 太郎",
  "relation": "長男",
  "years": "1930-2005",
  "generation": 0,
  "gender": "male",
  "deceased": true,
  "memo": "東京在住",
  "photo": null,
  "position": {"x": 0.5, "y": 0.2},
  "spouseId": 2,
  "spouseIds": [2],
  "spouseRelationshipTypes": {"2": "married"},
  "parentIds": [],
  "parentRelationshipTypes": {},
  "relationshipType": "married",
  "relationshipMeta": {}
}
```

- `generation`: 0が最上位世代です。5世代以上も扱えるようにしています。
- `position`: 手動配置した人物枠の位置です。用紙全体に対する0〜1の正規化座標で保存し、未指定または `null` の場合は自動配置します。
- `relation`: 「長男」「母」「配偶者」など、基準人物から見た続柄です。フォームでは候補から選ぶことも自由入力もできます。Canvas上の人物枠にも表示します。
- `relation` の自動候補は、同じ親を持つ人物の生年・ID順から `第N子` を提案します。性別を推測せず、必要に応じて手動で修正できます。
- `spouseId`: 旧形式互換用の代表配偶者IDです。保存時は `spouseIds` と相手側の配偶者情報も可能な範囲で同期します。
- `spouseIds`: 複数の配偶者IDを保持する拡張フィールドです。画面では人物ピッカーで選びます。`spouseId` は旧形式との互換用に先頭のIDを保持します。
- `spouseRelationshipTypes`: 配偶者IDごとの `married`、`divorced`、`widowed`、`partner` を保持します。画面では配偶者1人ずつに種別を設定でき、相手側の人物にも同じ種別が入ります。
- `parentIds`: 親IDの配列です。0人、1人、2人を想定しています（画面では2人を超えて選べません）。
- `parentRelationshipTypes`: 親IDごとの関係種別です。`biological`（実親）、`adopted`（養親）、`step`（継親）、`unknown`（不明）を保持します。未指定の既存データは実親として扱います。
- `relationshipType`: `married`、`divorced`、`widowed`、`partner` などを保持できます。
- `gender`: `male`、`female`、`other`、`unknown` を保持します。Canvas上では男性を□、女性を○の記号で示します（色に頼らないので白黒印刷でも伝わります）。
- `deceased`: 故人かどうかです。未指定の場合は `years` に終年があるか（`1888-1962` は故人、`1948-` は存命）で判断します。指定があればそちらを優先します。
- `memo`: 「東京在住」などの短い補足です。入力があると人物枠に1行追加します。
- `photo`: 人物写真です。取り込み時に長辺160pxのJPEGへ縮小したデータURLだけを保持します（`localStorage` を圧迫しないため、上限を超えるものと外部URLは捨てます）。
- `relationshipMeta`: 離婚、死別、養子などの詳細拡張用の空きフィールドです。

`localStorage` には次のキーを使います。

- `familytree.people`: 現在の人物データです。
- `familytree.paperSize`: 選択中の用紙サイズです。
- `familytree.backups`: 自動バックアップ（最大5件、新しい順）です。

## レイアウト方針

- `generation` ごとに横一列へ自動グルーピングします。
- 並べたあと、「子を親の下へ」「親を子の真ん中へ」の調整を数回くり返して家族のまとまりを揃えます。左右の並び順は変えないので、線の交差が増えることはありません。締めくくりは下から上の調整にしているため、**親夫婦は子どもたちの中央に来ます**。
- 写真や備考を使っている場合は、人物枠を縦に広げて収めます。写真のない人がいても文字の高さは揃えます。
- 同世代の配偶者ネットワークはひとまとまりにして隣接配置し、関係ごとに線で結びます。複数配偶者にも対応します。
- 親子関係は親側から下に伸ばし、子の世代で横バスラインへ分岐します。
- 養親・継親・不明な親子関係は、親子線を点線系の表示にして区別します。
- 手動配置を保存した人物は、画面サイズやA3/A4を切り替えても同じ比率位置を基準に再配置します。
- 兄弟姉妹や夫婦単位が増えた場合も全体を選択中の用紙比率のCanvas内に収まるよう自動スケーリングします。

## 印刷方針

Canvasのプレビューをブラウザの印刷対象として表示し、選択中のA3横（420 x 297 mm）またはA4横（297 x 210 mm）で印刷します。PDFファイルが必要な場合は、ブラウザの印刷画面で保存先にPDFを選択してください。

## 補足

配布は単一ファイルのまま、ソースは `src/` に分割しています。描画（`draw.js`）・配置（`layout.js`）・データ（`data.js`）はDOMから切り離してあるため、ユニットテストから直接呼び出せます。
